# Linux Core Concepts — Study Notes

## 1. Linux Kernel

The **Linux kernel** is the core of the operating system. It acts as a bridge between software applications and computer hardware.

### Main responsibilities
- **Process management:** Manages running processes.
- **Memory management:** Allocates and manages RAM.
- **Device management:** Communicates with hardware devices.
- **File system management:** Manages access to files and storage.
- **Networking:** Handles network communication.
- **Security:** Enforces permissions and access controls.

### Check the kernel version

```bash
uname -r
uname -a
```

- `uname -r` — displays the kernel release version.
- `uname -a` — displays general system and kernel information.

## 2. Kernel Space vs User Space

### Kernel Space
Kernel space is the privileged area where the kernel runs and directly manages hardware and system resources.

Examples:
- Device drivers
- Memory management
- Process scheduling
- Network drivers

### User Space
User space is where normal applications and user processes run with restricted privileges.

Examples:
- Bash shell
- Text editors
- Web browsers
- Docker CLI
- Linux commands such as `ls` and `cat`

### How they communicate

Applications request services from the kernel through **system calls**.

Example:

When you run `cat file.txt`, the command requests that the kernel read the file and provide its contents.

**Remember:** User space runs applications; kernel space manages system resources and hardware.

## 3. Working with Hardware

Linux provides commands to inspect hardware devices, system resources, and kernel messages.

### 3.1 `dmesg` — Kernel Messages

Displays messages generated by the kernel, including hardware detection and device-driver information.

```bash
dmesg
dmesg | less
dmesg | grep -i usb
dmesg | grep -i ethernet
```

Use `dmesg` to investigate hardware detection and driver-related problems.

Some systems restrict access to kernel logs. If permitted, use:

```bash
sudo dmesg
```

### 3.2 `udevadm info` — Device Information

`udev` manages device events and device nodes. `udevadm` provides information about devices.

```bash
udevadm info --help
udevadm info --query=all --name=/dev/sda
```

Replace `/dev/sda` with an existing device on your system.

To inspect a device using its system path:

```bash
udevadm info --attribute-walk --path=/sys/class/net/eth0
```

Replace `eth0` with an actual interface name.

### 3.3 `lspci` — PCI Devices

Lists PCI devices such as Ethernet controllers, graphics cards, and some storage controllers.

```bash
lspci
lspci | grep -i ethernet
lspci -nn
```

Example output:

```text
Ethernet controller: Intel Corporation ...
```

The vendor in this example is Intel Corporation.

### 3.4 `lsblk` — Block Storage Devices

Displays disks, partitions, and their relationships.

```bash
lsblk
lsblk -f
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
```

Common fields:
- `NAME` — device name
- `SIZE` — device size
- `TYPE` — disk or partition
- `FSTYPE` — filesystem type
- `MOUNTPOINTS` — mounted locations

### 3.5 `lscpu` — CPU Information

```bash
lscpu
```

Displays CPU architecture, cores, threads, and processor information.

### 3.6 `lsmem` — Memory Layout

```bash
lsmem
lsmem --summary
```

Displays the system memory-block layout and related information. Availability depends on the Linux distribution and installed utilities.

### 3.7 `free -m` — Memory Usage

```bash
free -m
free -h
```

- `free -m` — displays memory figures in MiB.
- `free -h` — displays memory figures in a human-readable format.

Important fields:
- `total` — total memory
- `used` — memory currently used
- `free` — completely unused memory
- `available` — estimated memory available for new applications without swapping

### 3.8 `sudo` — Administrative Privileges

`sudo` runs an authorized command with elevated privileges.

```bash
sudo command
sudo dmesg
sudo systemctl get-default
```

Use `sudo` only when needed. It does not mean that every command must be run as root.

## 4. Linux Boot Sequence

The boot sequence is the process through which a computer starts Linux.

### Main stages

**1. BIOS/UEFI**

- Initializes essential hardware.
- Performs POST (Power-On Self-Test).
- Selects a boot device.

**2. Bootloader — GRUB2**

- Loads the selected operating system's kernel.
- May load an initial RAM filesystem (initramfs).
- Allows the user to select a boot entry when configured.

**3. Kernel Initialization**

- Initializes CPU, memory, and device drivers.
- Detects hardware.
- Uses initramfs when needed to access the root filesystem.
- Prepares the system to start user-space processes.

**4. Init Process — systemd**

- The kernel starts the initial user-space process, normally PID 1.
- On many modern Linux distributions, PID 1 is `systemd`.
- `systemd` starts services and brings the system to its configured target.

### Boot sequence summary

```text
BIOS/UEFI
    ↓
POST and hardware initialization
    ↓
GRUB2 bootloader
    ↓
Linux kernel and initramfs
    ↓
PID 1 (systemd on most modern systems)
    ↓
Services and systemd target
    ↓
Login prompt or graphical desktop
```

### Useful commands

```bash
uname -r
systemctl status
systemctl list-units --type=service
systemctl get-default
```

## 5. Runlevels and systemd Targets

Older Linux systems used **runlevels** to represent operating modes. Modern systems commonly use **systemd targets**.

### Common runlevels and equivalent targets

| Traditional runlevel | Meaning | systemd target |
|---|---|---|
| 0 | Halt/shutdown | `poweroff.target` |
| 1 | Single-user/rescue mode | `rescue.target` |
| 2 | Multi-user mode; historically distribution-dependent | No universal equivalent |
| 3 | Multi-user, usually text-based | `multi-user.target` |
| 4 | Custom or unused, depending on distribution | No universal equivalent |
| 5 | Graphical multi-user mode | `graphical.target` |
| 6 | Reboot | `reboot.target` |

### Check the default target

```bash
systemctl get-default
```

Example output:

```text
graphical.target
```

### Change the default target to multi-user mode

```bash
sudo systemctl set-default multi-user.target
```

Verify:

```bash
systemctl get-default
```

Expected output:

```text
multi-user.target
```

### Change the default target to graphical mode

```bash
sudo systemctl set-default graphical.target
```

### Switch targets immediately

To switch the currently running system to multi-user mode:

```bash
sudo systemctl isolate multi-user.target
```

To switch to graphical mode:

```bash
sudo systemctl isolate graphical.target
```

**Caution:** `isolate` can stop services that are not required by the target. Switching targets may terminate your graphical session. In a lab, use it only when appropriate.

**Important difference:**
- `systemctl set-default` changes the target used by default during future boots.
- `systemctl isolate` switches the current system to a target immediately.

## 6. Linux File Types

Linux represents many resources through a filesystem interface. Common file types include:

| Type | Meaning | Example |
|---|---|---|
| Regular file | Stores text, program data, or other content | `/etc/hostname` |
| Directory | Contains directory entries | `/etc` |
| Character device | Handles data as a stream of characters | `/dev/null` |
| Block device | Handles data in blocks | `/dev/sda` |
| Symbolic link | Points to another path | `/bin` on systems where it links to `/usr/bin` |
| FIFO (named pipe) | Allows processes to communicate through a pipe | Created using `mkfifo` |
| Socket | Enables local or network communication between processes | `/run` service sockets |

### Identify file types

```bash
ls -l
file /etc/hostname
stat /etc/hostname
```

In `ls -l` output, the first character indicates the file type:

- `-` — regular file
- `d` — directory
- `l` — symbolic link
- `c` — character device
- `b` — block device
- `p` — FIFO
- `s` — socket

## 7. Linux Filesystem Hierarchy

Linux organizes files under a single root directory represented by `/`.

### Important directories

| Directory | Purpose |
|---|---|
| `/` | Root of the entire filesystem hierarchy |
| `/root` | Home directory of the root user |
| `/home` | Home directories of regular users |
| `/etc` | System-wide configuration files |
| `/bin` | Essential user commands; often linked to `/usr/bin` on modern distributions |
| `/sbin` | Essential system commands; often linked to `/usr/sbin` |
| `/lib` | Essential shared libraries and kernel-related files; may link to `/usr/lib` |
| `/usr` | Installed applications, libraries, documentation, and other shareable files |
| `/var` | Frequently changing data such as logs, caches, and spool files |
| `/tmp` | Temporary files |
| `/dev` | Device files representing devices and certain kernel interfaces |
| `/proc` | Virtual filesystem exposing process and kernel information |
| `/sys` | Virtual filesystem exposing device and kernel information |
| `/boot` | Bootloader files, kernels, and related boot files |
| `/run` | Runtime state data created since boot |
| `/mnt` | Common temporary mount point for filesystems |
| `/media` | Common mount point for removable media |
| `/opt` | Optional/add-on application software |
| `/srv` | Data served by system services |

### Important differences

- `/root` is the root user's home directory.
- `/` is the root of the entire filesystem.
- `/home/bob` is an example of a regular user's home directory.
- `/etc` stores configuration files; it is not intended for ordinary personal files.
- `/proc` and `/sys` are virtual filesystems, not ordinary collections of files stored on disk.

### Explore the filesystem

```bash
pwd
ls /
ls -l /etc
ls -l /home
ls -ld /root
df -h
findmnt
```

Use `sudo` if access to a directory or command requires elevated privileges.
